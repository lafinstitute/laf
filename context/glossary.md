# Glosariusz LAF

**Źródło: LAF 1.6, Glossary oraz sekcje 3–5.** Definicje zachowują znaczenie przewodnika; dodatkowe uwagi oznaczono jako objaśnienia.

| Termin | Znaczenie |
|---|---|
| **Application** | Program lub grupa programów przeznaczonych dla użytkownika końcowego. |
| **Component** | Program lub grupa programów realizujących co najmniej jedną Capability; może to być aplikacja, usługa chmurowa, integracyjna, mikroserwis i inny element. |
| **Capability** | Zdolność aplikacji/komponentu do wykonywania podstawowych funkcji potrzebnych organizacji; może odpowiadać procesowi, zadaniu lub źródłu danych. |
| **Requirements** | Wymagania definiowane przez biznes dla aplikacji i komponentów. |
| **Reference Architecture (RA)** | Długoterminowa wizja docelowego środowiska dla obszaru biznesowego. |
| **Standards (ST)** | Zasady i wymagane modele zapewniające niezbędną spójność środowiska. |
| **Component Passport (CP)** | Zwięzły opis stanu konkretnego komponentu. |
| **Component Portfolio Assessment (CPA)** | Praktyka gromadzenia i oceny informacji o portfelu komponentów. |
| **Solution Vision (SV)** | Wysokopoziomowy projekt rozwiązania odpowiadający konkretnej potrzebie biznesowej. |
| **Architecture Repository (REPO)** | Centralne repozytorium artefaktów architektonicznych LAF. |
| **Architectural Forum** | Główna przestrzeń współpracy architektów nad sprawami przekrojowymi. |
| **SDLC** | Software Development Life Cycle — cykl życia wytwarzania oprogramowania. |
| **NFR** | Non-Functional Requirements — wymagania niefunkcjonalne, np. bezpieczeństwo. |
| **RIM** | Reference Implementation Metric — wskaźnik zgodności Solution Visions. |
| **ARM** | Application Reference Metric — relacja liczby aplikacji ogółem do liczby Investment i Tolerance. |
| **ICRM** | Implemented Capabilities Redundancy Metric — relacja wdrożonych instancji zdolności do wartości docelowej. |
| **CRM** | Capability Reference Metric — relacja używanych zdolności do zdolności z RA. |
| **MRAC** | Machine-Readable Architecture Context — maszynowo czytelna, zsynchronizowana pochodna treści RA, ST i CP. |
| **AI Footprint** | Udział kodu lub logiki komponentu wygenerowanej przez AI, uwzględniany jako wymiar CPA w LAF 1.6. |
| **Fast Track** | Uproszczona ścieżka dla drobnych zmian w jednej aplikacji, które nie zmieniają podstawowych zdolności. |

LAF traktuje terminy Application i Component zamiennie w wielu praktykach, choć Component ma szersze znaczenie.

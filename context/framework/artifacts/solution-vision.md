# Solution Vision (SV)

**Źródło: LAF 1.6, sekcja 3.1.4.**

SV to wysokopoziomowy projekt architektoniczny odpowiadający na konkretną potrzebę biznesową. Stanowi przyrost na drodze do Reference Architecture i może wprowadzać komponenty, zmieniać rozmieszczenie zdolności albo wycofywać przestarzałe aplikacje i technologie.

SV jest inicjowane przez wymagania biznesowe w ramach SDLC. Opisuje logiczne komponenty, zdolności, wzorce interakcji, zmiany infrastruktury oraz kluczowe NFR, w tym bezpieczeństwo. Powinno uwzględniać Reference Architecture, Component Passports i Standards.

Architekt tworzy wizję we współpracy z biznesem i inżynierami. Szczegółowy projekt funkcjonalności w aplikacji należy do zespołu implementującego. Zmiany powinny być ograniczone do tych, które przynoszą wartość organizacyjną i wzrost techniczny.

## Pytania kontrolne

- Jakie wymaganie biznesowe uruchamia SV?
- Jakie zdolności lub komponenty są zmieniane?
- Jak rozwiązanie odnosi się do RA, CP/CPA i Standards?
- Jakie są najważniejsze NFR i zależności?
- Jaki jest przyrost, korzyść oraz istotne kompromisy?
